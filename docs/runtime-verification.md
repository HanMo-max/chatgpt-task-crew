# 核对实际运行

本模板声明的是期望分工。实际生效要在目标项目的新会话中检查。

## 四层证据

| 层次 | 可以证明什么 | 不能替代什么 |
|---|---|---|
| TOML / Skill | 默认模型、角色和规则已经写入 | 不能证明会话加载或模型实际运行 |
| 子 Agent 工具请求与返回 | 真正派发了什么任务、请求哪个模型、是否成功启动 | 不能独自证明服务端最终模型 |
| 子会话运行元数据 | 客户端记录的运行模型与推理强度 | 不能证明任务正确、业务验收或最终计费 |
| 文件、检查与验收结果 | 任务完成到什么程度 | 不能反推模型路由、成本或提速比例 |

能获取哪层就报告哪层，缺失证据时写明“未验证”。不把客户端元数据等同于独立服务端计费凭证。

## 隔离验证提示

在一个新建的临时项目合并模板后，可让主控执行：

```text
这是一轮模型分工验收，明确要求实际使用两个子 Agent。
在此隔离项目内，派一个 Luna worker 创建 calculator.py 和 test_calculator.py，
实现 add(left, right)，验证 add(2, 3) == 5。
worker 完成后再派一个 Luna tester，只读核对源文件并执行该行为验证。
不安装依赖，不改全局配置，不上传内容。
报告两次真正的派发请求、工具返回、能获得的子会话模型信息及测试结果。
不能获取实际运行模型时，分别列出请求模型与未验证部分。
```

这里只为核验委派而明确要求两个 Agent。日常这种琐碎计算器任务无需两个 Agent。
如果环境没有 pytest，可以直接导入并调用测试函数；明确记录 pytest 未运行，不能写成 pytest PASS。

## 顺序与所有权

worker 拥有两个待创建的文件；tester 在 worker 完成后读取与验证。
测试可以生成本地缓存或隔离测试产物，但不得改生产源码来使验证通过。
验证前记录需要修改的文件，验证后检查是否出现范围外改动，清理无用临时文件。

## 发布前需要说清楚

源项目运行记录验证了源项目；整理后的模板经过静态检查仍需要目标客户端加载测试。
模型默认值不会锁定用户的实时选择。使用 Sol 主控的验证不能被报告成 Astra 主控通过。
如需评价成本或速度，使用同类任务的配对运行，记录模型、tokens、耗时、返工和验收结果。
