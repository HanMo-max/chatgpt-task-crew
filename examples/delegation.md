# 委派契约示例

把路径、目标和验收条件替换为实际任务的信息，不需要照搬所有角色。

## 只读探索

```text
角色：explorer；模型：gpt-6-luna；推理：medium。
目标：确认“保存草稿”真实入口到持久化写入的调用路径。
范围：app/ 和对应配置、测试；只读，不修改文件。
背景：父 Agent 正在定位保存后重启数据丢失的问题。
输出：入口、调用链、相关文件/符号、已有测试、未确定项。
验收：每个结论有源码证据，不根据文件名猜调用路径。
```

## 有边界实现

```text
角色：worker；模型：gpt-6-luna；推理：medium。
目标：按父 Agent 已确定的方案修复保存请求中的字段传递。
所有权：只允许修改 app/save.py；其他 worker 不编辑此文件。
约束：保持现有接口与数据结构，不新增依赖，不改业务语义。
输出：改动、必要验证和遗留问题。
验收：复现步骤中的字段完整到达现有写入函数；范围外文件无改动。
遇到需要修改 schema 的情况先返回证据，不扩大实现范围。
```

## 独立验证

```text
角色：tester；模型：gpt-6-luna；推理：medium。
前提：对应 worker 已完成；读取最终版本。
目标：用隔离测试目录验证保存后重启仍能恢复字段。
约束：不改源码、不改测试、不安装依赖。
输出：实际命令、结果、关键输出和覆盖缺口。
验收：复现原问题的同一路径成功；缺依赖时如实报告未运行的检查。
```

## 独立审查

```text
角色：reviewer；模型：gpt-6-astra；推理：low。
输入：最终 diff、需求和验证证据。
目标：查找保存路径的正确性、数据回归与共享状态问题。
约束：只读，不代替 worker 修改文件。
输出：具体发现的严重度、文件/符号、影响和建议；无发现时说明验证范围。
验收：每个发现可复现或有清楚的因果依据，不返回纯排版意见。
```

实际派发时按当前工具 schema 选择角色和上下文继承方式；不要将上述文本当作工具参数格式。
